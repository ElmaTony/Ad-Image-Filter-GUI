在项目根目录运行。GUI 自动化可设置 `QT_QPA_PLATFORM=offscreen`，无需弹出窗口。离屏平台会显式注册本机中文字体用于截图。文件操作与用户配置全部使用测试临时目录。

2026-11-18 二维码回归涵盖 EAN-13、带定位图案的方格及条纹、带徽标模糊码、普通文本码、旋转的损坏码、多码命中理由和旧缓存失效。未解码候选需通过定位图案、双轴时序和两份格式信息校验。解码接口参考 [pyzbar 的符号限制](https://github.com/NaturalHistoryMuseum/pyzbar/blob/master/pyzbar/pyzbar.py) 和 [OpenCV 的解码返回值](https://docs.opencv.org/4.4.0/de/dc3/classcv_1_1QRCodeDetector.html)。本轮二维码回归 7 项、引擎与审查修复回归 28 项、工作台 28 项、GUI 自测 131 项及 E2E 37 项均通过。原有精度集 22 个正样本全部命中，22 个负样本无误报。基线 `8f4d833` 的 12 张合成图和 7 张本地只读图片逐字段对照一致。另用独立临时工作台验证方格图不会进入待审，损坏码显示新提示。

暂停自测在测试内给快速解码留出操作时间，并依据扫描完成状态判断继续后是否结束。最终 EXE 的 `--selftest`、`--gui-test` 和 `--smoke` 均退出 0。用户配置、缓存、操作日志和扫描历史与交付检查前一致。

## 需要真实样本的用例

`test_e2e.py` 需要 `testdata/real4_*` 与 `real6_*` 真实广告样本（个人数据，**不随仓库分发**，被 `.gitignore` 排除）。精度测试不依赖这些真实图片。换机器时：

- 没有样本：E2E 会明确报缺失，其余合成测试不受影响
- 有样本：把广告图放进 `testdata/`，文件名以 `real` 开头即可被自动纳入（如 `real4_*.jpg`、`real6_*.png`）
- 合成样本兜底：`python ad_filter.py --make-fixtures` 可重新生成 `type1/type2/normal_*` 等合成图（覆盖大部分精度用例）

## 测试覆盖内容速览

- **test_e2e.py**：启动空状态 → 添加文件夹 → 扫描（暂停/继续/当前文件/进度打勾）→ 筛选 → 勾选链（Ctrl+A toggle/反选/点圈）→ Lightbox（入场/缩放/Esc）→ 标记保留 → 隔离处置 → 恢复 → 二次扫描缓存 → 改规则缓存失效 → 主题切换 → 移除文件夹 → 关闭
- **test_accuracy.py**：6 类广告正样本（拼图+QR / 长条 / 中央透明水印 / 角落小水印 / 深底白字 / 模糊小字）+ 6 类干扰负样本（普通风景 / 正常文字菜单 / 版权水印 / 图表 / 纯色壁纸 / 手机截图），统计召回率与误报率
- **test_workbench.py**：独立异常筛选、大小写搜索、跨筛选全选、隐藏项确认、隔离撤销、删除范围、导入控件同步、完整 OCR、焦点保持、任务禁用态、多文件夹与小窗口。
- **audit_ui.py**：标题栏按钮几何、顶栏/筛选条高度、网格单元尺寸、无侧栏断言、底部停靠完整性、像素级语义色（执行处置=红、品牌橙在场）
- **preview_layouts.py**：用临时合成数据输出大图横/竖图及纯净查看截图到 `_preview/`；`--interactive` 可用于原生窗口检查。
- **preview_dialogs.py**：使用独立合成历史、图片和隔离清单输出深浅主题弹窗截图到 `_preview/dialogs/`。
- **preview_workbench.py --output <目录>**：使用临时合成图片和独立配置、缓存、历史、日志、隔离区，输出首次启动、混合分类、隐藏已选、全部已选、筛选空结果、异常、日志、多文件夹和窄屏的 Qt 截图；输出位置由调用者指定。
